# TCP vs UDP

handshake란?  
말 그대로 악수 즉, "상호 확인". 악수는 한 손만 내밀면 안되고 양쪽이 동시에 손을 맞잡아야 성립된다.  
마찬가지로 통신에서도 한쪽이 일방적으로 보내는 게 아니라 양쪽이 서로 "나 준비됐어"를 주고 받는 것

3-way-handshake : 3번 악수를 주고 받는 절차

handshake(TCP 안에 포함된 절차)로 연결이 수립되면 이제 실제 데이터를 주고받는 단계

---

1. TCP (Transmission Control Protocol) - "확실하게 보내자"

연결 지향 프로토콜이다. 데이터를 보내기 전에 먼저 상대방과 연결을 수립하고 (handshake), 패킷 순서, 재전송, 흐름제어를 프로토콜 자체가 처리한다.  
즉, 클라이언트 요청 → 서버 승낙/거부 → 승낙 시에만 진행

연결할 때만이 아닌 전체 과정에서도 그런다.  
연결할 때는 서버가 수락해야 연결되고, 데이터를 보낼 때도 상대가 "받았어"라고 확인해야 다음 데이터를 보내고, 끊을 때도 상대가 "알았어"라고 해야 끊어짐  
보통 웹에서 일어나는 모든 통신이 TCP이다.

---

2. UDP (User Datagram Protocol) - "일단 빨리 보내자"

비연결 프로토콜이다. handshake 없이 데이터그램을 바로 던지고 도착 여부, 순서를 보장하지 않는다.  
실시간성이 중요한 곳에 사용됨  
ex) 실시간 영상, 음성 통화 등

---

신뢰성 vs 속도 (trade off = 하나를 얻으면 하나를 잃는다)  
TCP는 매번 확인하여 신뢰성이 높고 UDP는 확인 없이 던지니까 속도가 빠르다.

포트란 : 같은 컴퓨터 안에서 어떤 서비스인지 구분하는 번호 (HTTP: 80 / HTTPS: 443)

---

3-way handshake 확인 신호 (SYN → SYN+ACK → ACK)  
1단계 SYN : 내가 요청  
2단계 SYN+ACK : 상대가 받음 + 요청  
3단계 ACK : 내가 확인
