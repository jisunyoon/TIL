# HTTPS + TLS 핸드셰이크

HTTPS는 HTTP 통신을 TLS로 암호화하는 프로토콜이다.

TLS 핸드셰이크는 클라이언트와 서버가 암호 알고리즘 합의, 인증서 검증, 세션 키 교환을 거쳐 안전한 통신 채널을 수립하는 초기 협상 과정

---

## 순서

**1. 합의 단계 (클라이언트 → 서버)**  
클라이언트와 서버가 TLS 버전을 합의하고 서버가 인증서(공개키)를 클라이언트에게 전달

**2. 키 전달 (클라이언트 → 서버)**  
클라이언트가 세션에 쓸 키를 만들어서 서버 공개키로 암호화해 전송

**3. 서버 복호화 (클라이언트와 서버가 키를 동일하게 가짐)**  
서버가 자신의 개인키로 복호화해서 그 키 확인 → 양측이 같은 세션 키를 갖게 됨

**4. 검증 완료**  
양쪽이 그 키로 암호화한 Finished 메시지를 주고받아서 두 개가 잘 풀리면  
"같은 키를 공유하고 있다" = "검증 완료"

---

## 인증서 역할

공개키의 주인이 진짜 이 도메인의 소유자임을 CA가 보증하는 증명서
