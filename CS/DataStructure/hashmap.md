# 해시맵 (HashMap)

**키 → 값**으로 저장하고, 키로 **O(1)에 꺼내는** 자료구조

```js
const map = { apple: 3 };
map["apple"];   // 3 → 키로 바로 접근 O(1)
```

---

## 어떻게 O(1)인가

```
"apple" → [해시 함수] → 숫자(2) → 버킷[2]에 저장
다음에 "apple" 찾을 때 → 같은 해시 함수 → 바로 그 칸 → O(1)
```

1. **해시 함수**가 키를 숫자로 바꿈
2. 그 숫자를 **버킷(저장 칸) 번호**로 씀
3. 찾을 때 같은 계산 → 바로 그 칸 접근

> 앞에서부터 훑는 게 아니라 **계산으로 위치를 바로 알아내기** 때문에 O(1).

---

## 충돌 처리 (Collision)

**다른 키가 같은 버킷 번호로 나올 때** 처리하는 법.

서로 다른 키가 같은 버킷 번호로 계산되는 경우:

```
"apple" → 해시 → 2번 칸
"grape" → 해시 → 2번 칸   ← 같은 칸 (충돌!)
```

| 방식 | 설명 |
|---|---|
| **체이닝 (Chaining)** | 그 칸에 **링크드리스트로 사슬처럼 여러 개 연결**해서 담음 |
| **개방 주소법 (Open Addressing)** | 그 칸이 차 있으면 **옆 빈 칸**으로 가서 넣음 |

### 체이닝

한 칸을 덮어쓰지 않고, 여러 개를 사슬(chain)처럼 매달아 둔다.

```
버킷[2] → [apple:3] → [grape:5] → [melon:2]   ← 이 줄이 "체인(사슬)"
```

찾을 때: **해시로 버킷에 바로 점프(O(1)) → 그 칸의 사슬만 훑으며 키 비교**

- 충돌 적음 → 한 칸에 1개 → O(1) 유지
- 충돌 많음 → 사슬이 길어짐 → 최악 O(n)

### 개방 주소법

사슬을 안 만들고, 칸이 차 있으면 **옆 칸(3번, 4번…)으로 이동해 빈 자리**에 넣는다.

---

> 충돌이 많아지면 조회가 O(n)에 가까워질 수 있다.
> 그래서 **좋은 해시 함수**(특정 칸에 안 몰리고 골고루 흩어지게) + 적당한 버킷 수가 중요.
