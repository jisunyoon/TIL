# Big-O 표기법

데이터 개수(n)가 늘어날 때 코드의 **실행 시간(또는 메모리)이 얼마나 빠르게 증가하는지**를 나타내는 표기법

---

## 기본 개념

- 실제 몇 초인지가 아니라 **n이 커질 때의 증가 추세**를 본다
- 상수는 무시 → `2n`이든 `100n`이든 `O(n)`
- 보통 **최악의 경우(worst case)** 기준

---

## 대표 4가지 (빠른 순)

### O(1) — 상수 시간
n과 무관하게 **항상 일정한 시간**. 몇 번째인지 알면 바로 접근.

```js
arr[5]        // 배열 인덱스 접근
map.get(key)  // 해시맵 조회
obj.name      // 객체 프로퍼티 접근
```

### O(log n) — 로그 시간
한 단계마다 처리할 데이터가 **절반씩 줄어듦**. 대표 예시는 이진 탐색.

```js
// 정렬된 배열에서 target 찾기 — 가운데 보고 반을 버림
while (left <= right) {
  const mid = (left + right) >> 1;
  if (arr[mid] === target) return mid;
  if (arr[mid] < target) left = mid + 1;   // 왼쪽 절반 버림
  else right = mid - 1;                     // 오른쪽 절반 버림
}
```
> n이 2배가 돼도 단계는 딱 1번만 늘어난다. 조건: **절반씩 버릴 수 있어야** 함(정렬/트리 구조).

### O(n) — 선형 시간
**n개를 한 번씩 다 봄** → 개수에 정비례. n이 2배면 시간도 2배.

```js
for (const x of arr) { ... }   // 전체 순회, 합계, 정렬 안 된 값 찾기
```

### O(n²) — 제곱 시간
**반복문 안에 반복문** → n을 n번씩. n이 2배면 시간은 4배.

```js
for (const a of arr)
  for (const b of arr)         // 모든 쌍 비교 (버블 정렬 등)
    ...
```

---

## 증가 속도 비교

| n | O(1) | O(log n) | O(n) | O(n²) |
|---|---|---|---|---|
| 8 | 1 | 3 | 8 | 64 |
| 1,000 | 1 | 약 10 | 1,000 | 1,000,000 |
| 1,000,000 | 1 | 약 20 | 1,000,000 | 1조 |

> 빠른 순: **O(1) < O(log n) < O(n) < O(n²)**

---

## 시간 복잡도 vs 공간 복잡도

- **시간 복잡도** = 얼마나 **빠른가** (연산 횟수)
- **공간 복잡도** = 얼마나 **메모리를 쓰는가** (추가로 잡는 저장 공간)
- 표기법은 **똑같이 Big-O** 사용 (`O(1)`, `O(n)` …)

```js
// O(1) 공간 — 변수 몇 개만, n과 무관
let sum = 0;
for (const x of arr) sum += x;

// O(n) 공간 — n에 비례해 새 배열을 만듦
const doubled = arr.map(x => x * 2);   // 원소 n개짜리 배열 하나 더
```

- 공간 복잡도는 보통 **입력 자체는 빼고, 추가로 잡는 메모리**만 센다
  (위에서 `arr`은 입력이라 제외, 새로 만든 `doubled`가 O(n))

> **시간 ↔ 공간 트레이드오프** — 메모리를 더 써서(공간 ↑) 속도를 높이는(시간 ↓) 경우가 많다.
> ex) 계산 결과를 저장해두고 재사용 (캐싱 / 메모이제이션)
