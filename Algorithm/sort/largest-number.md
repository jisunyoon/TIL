# 가장 큰 수 (Lv.2, 정렬)

- **유형:** 정렬 (커스텀 비교 함수)
- **출처:** 프로그래머스

## 문제

```javascript
// 정수를 이어 붙여 만들 수 있는 가장 큰 수 (문자열로 return)
function solution(numbers) {
  var answer = '';
  return answer;
}

solution([6, 10, 2]);         // "6210"
solution([3, 30, 34, 5, 9]);  // "9534330"
```

## 핵심 고민: 그냥 큰 수부터 정렬하면 안 되나?

- ❌ 숫자 크기순: `[6, 10, 2]` → `[10, 6, 2]` → `"1062"` (틀림! 답은 `"6210"`)
- 10이 6보다 크지만, **이어 붙이면** `"610" > "106"` → 6이 앞에 와야 함
- → 기준은 "숫자 크기"가 아니라 **"어느 쪽을 앞에 붙여야 더 커지나"**

## 아이디어: 이어 붙여보고 비교

- 두 수 a, b를 **문자열로 이어 붙인 두 가지**를 직접 비교:
  - `a + b` (a를 앞에) vs `b + a` (b를 앞에)
  - 예: a=6, b=10 → `"610"` vs `"106"` → `"610"`이 크니 6이 앞
- 이 기준으로 전체를 정렬한 뒤 전부 이어 붙이면 끝

## 새 도구: sort의 비교 함수

```javascript
arr.sort((a, b) => 숫자);
// 음수 return → a가 앞으로
// 양수 return → b가 앞으로
// 0    return → 순서 유지
```

- 우리는 "b+a가 크면 b를 앞으로" → `(b + a) - (a + b)` 형태로 비교
- 문자열끼리는 `-` 연산이 안 되니 **숫자로 바꿔서** 빼기: `Number(b + a) - Number(a + b)`

## 풀이

```javascript
function solution(numbers) {
  const answer =  numbers.map((n) => String(n)).sort((a,b) => (b + a) - (a + b)).join("");

  return answer[0] === '0' ? '0' : answer;
}
```

## 자기 점검

- [ ] `[6, 10, 2]` → `"6210"`
- [ ] `[3, 30, 34, 5, 9]` → `"9534330"`
- [ ] `[0, 0, 0]` → `"0"` (엣지: "000" 아님!)
- [ ] `[40, 403]` → `"40403"` (`40403` vs `40340`)
