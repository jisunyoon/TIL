# 멀리 뛰기 (Lv.3, DP)

- **유형:** 동적 프로그래밍 (피보나치형 점화식) + 모듈러 연산
- **출처:** 프로그래머스

## 문제

```javascript
// 한 번에 1칸 또는 2칸씩 뛰어 n칸 끝에 도달하는 방법의 수
// 결과를 1234567로 나눈 나머지를 return
function solution(n) {
  let dp = [];
  dp[1] = 1;
  dp[2] = 2;

  for (let i = 3; i <= n; i++){
    dp[i] = (dp[i - 1] + dp[i - 2]) % 1234567
  }

  return dp[n];
}

solution(4); // 5
solution(3); // 3
```

`n = 4`일 때 5가지:
```
(1,1,1,1)  (1,2,1)  (1,1,2)  (2,1,1)  (2,2)
```

## 제한사항 읽기

- `n`: **1 ~ 2000**
- 결과를 **`1234567`로 나눈 나머지** → 답이 엄청 커진다는 뜻 (아래 함정 참고)

## 핵심 아이디어: "마지막 한 걸음"으로 쪼개기

n칸에 도달하는 모든 방법을 **마지막 걸음이 뭐였냐**로 나눠봅니다. 겹치지 않고, 빠짐도 없어요.

- 마지막이 **1칸**이었다면 → 그 직전엔 **n-1칸**에 서 있었음
- 마지막이 **2칸**이었다면 → 그 직전엔 **n-2칸**에 서 있었음

이 둘 말고는 없습니다(1칸 or 2칸뿐이니까). 그러므로:

```
(n칸 가는 방법) = (n-1칸 가는 방법) + (n-2칸 가는 방법)
```

**점화식:** `dp[n] = dp[n-1] + dp[n-2]` — 피보나치입니다.

## 시작값 (base case)

점화식은 앞의 두 개를 필요로 하므로 손으로 직접 세야 합니다.

- `dp[1] = 1` → `(1)`
- `dp[2] = 2` → `(1,1)`, `(2)`

확인: `dp[3] = 2 + 1 = 3` ✅ / `dp[4] = 3 + 2 = 5` ✅ (입출력 예와 일치)

## ⚠️ 함정: 나머지를 언제 구하나

- `n = 2000`이면 답은 **자릿수가 400개가 넘는 수**
- 자바스크립트 `Number`는 약 **9007조(2^53)** 를 넘으면 **정확도가 깨짐** → 값이 어긋나기 시작
- → **마지막에 한 번 `% 1234567` 하면 이미 늦음.** 답이 망가진 뒤임
- **매번 더할 때마다** 나머지를 취해야 함:
  ```
  dp[i] = (dp[i-1] + dp[i-2]) % 1234567;
  ```
- 나머지 연산은 덧셈과 순서를 바꿔도 결과가 같아서, 중간중간 해도 최종 답이 동일함

## 접근

- 배열 `dp` 준비, `dp[1] = 1`, `dp[2] = 2`
- `i`를 `3`부터 `n`까지 → `dp[i] = (dp[i-1] + dp[i-2]) % 1234567`
- `dp[n]` return
- **주의:** `n = 1`이면 반복문이 한 번도 안 돌고 `dp[1]`이 그대로 답 (`dp[2]`를 미리 넣어둔 게 문제되지 않는지 확인)
