# useState 동작 원리


## 학습 목표

- useState가 값을 어떻게 기억하는지
- 리렌더링이 정확히 언제 일어나는지

## 정리
useState란 컴포넌트가 기억해야 하는 값을 저장하고, 그 값이 바뀌면 
화면을 다시 그리게 해주는 것.
즉, 변하는 값을 상태(state)라고 부르고 그걸 다루는 게 useState이다.

일반 변수와 달리 useState는 값이 바뀌면 화면(UI)을 자동으로 다시 그려준다.

const [값, set함수] = useState(초기값)
- 값 = 지금 상태 (직접 바꿀 순 있지만 React가 감지 못 함 → set함수 써야 함)
- set함수 = 값을 바꾸는 함수 (+ "화면 갱신해!" 신호도 같이 보냄)

useState가 값을 기억하는 이유 = 값이 컴포넌트가 아니라 React 쪽에 
저장돼 있어서, 그걸 가져오기 때문.
즉, 컴포넌트가 다시 실행돼도 값은 React가 바깥에 들고 있으니까 안 사라진다.
useState는 그걸 꺼내오는 역할이다.
- 기억 = React가 값을 보관 (저장)
- 바꾸기 = set함수로 그 보관된 값을 수정

리렌더링은 set함수를 호출하고, 값이 이전과 다를 때 일어난다.
(같은 값으로 바꾸면 리렌더 안 됨)

React는 "주소(참조)가 바뀌었나"로 변화를 판단한다:
- setObj(obj);          // 같은 주소 → "안 바뀌었네" → 리렌더 X
- setObj({ ...obj });   // 새 주소 → "바뀌었네" → 리렌더 O
→ 그래서 객체는 새로 만들어야 화면이 갱신됨 (불변성)
