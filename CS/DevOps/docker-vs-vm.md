# Docker (컨테이너) vs VM

둘 다 **한 컴퓨터 안에서 격리된 실행 환경을 만드는 것**. 격리 수준과 무게가 다르다.

---

## VM (가상머신)

한 컴퓨터 안에, **OS까지 통째로 갖춘 "가짜 컴퓨터"를 하나 더** 만드는 것.
내 컴퓨터(윈도우) 안에서 소프트웨어로 리눅스 컴퓨터 한 대를 통째로 돌리는 것. OS부터 새로 깔아 완전히 독립된 컴퓨터처럼 동작한다.

- **장점** — 완전히 독립적(서로 영향 없음, 격리 강력), 다른 OS도 자유롭게
- **단점** — OS를 통째로 가지니 무겁고(GB 단위) 느림, 부팅도 수십 초

```
┌──────────────┐
│     앱        │
│  게스트 OS    │  ← VM마다 OS를 통째로 가짐 (그래서 무거움)
├──────────────┤
│  Hypervisor  │  ← 물리 컴퓨터 위에 여러 VM을 만들고 관리하는 층
├──────────────┤
│   물리 컴퓨터  │
└──────────────┘
```

---

## 컨테이너 (Docker)

OS는 새로 안 깔고(**호스트 것을 빌려 씀**), 앱 실행에 필요한 것만 격리해서 담는 것.

- **장점** — OS가 없으니 가볍고(MB 단위) 빠름, 켰다 껐다 순식간
- **단점** — 호스트 OS 커널을 공유해서 VM보다 격리는 약함

> Docker의 핵심은 **저장(담기)이 아니라 실행**이다. 앱을 격리된 상태로 돌리는 게 목적.
> 흐름: **앱 코드 + 라이브러리 + 설정을 이미지에 모아 담고 → 컨테이너로 실행**

---

## 둘의 본질 차이

| | 무엇을 하나 | 무게 | 격리 |
|---|---|---|---|
| **VM** | 컴퓨터 환경 자체를 통째로 복제 | 무거움 (GB) | 강함 |
| **컨테이너** | 앱 + 필요한 환경만 모아 실행 | 가벼움 (MB) | 약함 |

비유:
- **VM** = 집을 통째로 새로 지음 (OS 포함)
- **컨테이너** = 셰어하우스 방 하나 빌림 (OS 공유)

---

## Docker vs Docker Compose

**Docker** — 컨테이너 하나를 만들고 실행하는 기본 도구. 하나씩 따로 명령.

```bash
docker run frontend   # 프론트 컨테이너 실행
docker run backend    # 백엔드 컨테이너 실행
docker run db         # DB 컨테이너 실행
```

→ 앱이 프론트+백엔드+DB처럼 여러 개면 하나씩 치기 번거롭다.

**Docker Compose** — 여러 컨테이너를 **파일 하나(YAML)에 정의**해 한 번에 켜고 끈다.

```yaml
# docker-compose.yml
services:
  frontend:
    image: my-frontend
    ports: ["80:80"]
  backend:
    image: my-backend
    ports: ["3000:3000"]
  db:
    image: postgres
```

```bash
docker-compose up     # 프론트+백엔드+DB 한 번에 실행
docker-compose down   # 한 번에 종료
```

| | 다루는 대상 | 방식 | 언제 |
|---|---|---|---|
| **Docker** | 컨테이너 1개 | 명령어로 하나씩 | 단순할 때 |
| **Docker Compose** | 컨테이너 여러 개 | YAML로 한 번에 | 프론트+백+DB 같이 띄울 때 |

비유: Docker = 악기 하나 연주, Compose = 오케스트라 지휘(여러 개를 한 악보로 조율).

## 배포 흐름에서의 층위

실제 배포는 **SSH로 서버 접속 → 그 안에서 Docker로 컨테이너 실행/관리** 순서다.

```
내 컴퓨터
  └─ Termius(SSH)로 접속 → 서버(보통 VM)
                            └─ 그 안에서 Docker로 컨테이너 실행
                                 ├─ 프론트 컨테이너
                                 ├─ 백엔드 컨테이너
                                 └─ DB 컨테이너
```

- **VM = 접속한 서버(컴퓨터) 자체**, **프로젝트 = 그 서버 안에 든 파일들**
  (Termius로 접속한 건 "프로젝트"가 아니라 "서버 한 대". 클라우드 서버는 대부분 VM)
- 배포 시엔 **밖에서 컨테이너를 조종**(실행·로그·재시작)하는 게 대부분

```bash
docker ps               # 돌아가는 컨테이너 목록
docker-compose up -d    # 컨테이너들 백그라운드 실행
docker logs 컨테이너명   # 로그 확인
docker exec -it 컨테이너명 bash   # (가끔) 컨테이너 내부로 들어가 디버깅
```

> 컨테이너 "안에 들어가는" 건 `docker exec`로 문제 생겼을 때 가끔 하는 것이지, 배포 때 매번 하는 게 아니다.
