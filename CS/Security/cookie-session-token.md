# 쿠키 vs 세션 vs 토큰

## 쿠키란?

브라우저에 저장되는 작은 데이터 조각  
서버가 응답할 때 `Set-Cookie` 헤더로 보내면, 브라우저가 저장했다가 같은 도메인에 요청할 때마다 자동으로 함께 전송한다.

주요 옵션: `HttpOnly`, `Secure`, `SameSite` (다른 사이트에서 우리 서버로 요청 보낼 때 쿠키 실어 보내지 마), 만료시간

---

## 세션이란?

서버 쪽에서 사용자 상태를 저장하는 방식  
쿠키는 저장소, 세션은 "서버가 사용자를 식별, 관리하는 개념"

1. 로그인 성공 시 서버가 세션 ID 생성 (거기에 사용자 정보가 있음)
2. 클라이언트에게는 세션 ID만 쿠키로 전달
3. 그 이후 요청마다 브라우저가 세션 ID를 보내면 서버가 그 ID로 저장소를 조회해 사용자 식별

★ 세션은 서버가 상태를 저장 (Stateful) → 서버 여러 대면 세션 공유 문제 생김

---

## 토큰이란? (Token, JWT)

사용자 정보 자체를 암호학적으로 서명해서 클라이언트에 저장하는 방식 (서버가 상태를 저장하지 않아도 됨)

1. 로그인 성공 시 서버가 사용자 정보를 담은 토큰을 만들고 비밀키로 서명해 전달
2. 이후 요청마다 클라이언트가 `Authorization: Bearer <토큰>` 헤더로 전송
3. 서버는 서명만 검증하면 됨

★ 토큰은 서버가 상태를 저장 안 함 (Stateless) → 서버 여러 대여도 상관없음

JWT 구조: 헤더, 페이로드, 서명

---

## 그 외 저장소

**localStorage**  
영구적으로 저장되는 키-값 저장소  
사용자가 직접 지우거나 코드로 삭제하지 않는 한 계속 남아있다.

**sessionStorage**  
탭 단위로 유지되는 임시 저장소  
API는 localStorage와 똑같지만 생명주기만 다르다.  
브라우저를 닫지 않고 탭만 닫아도 데이터가 사라짐
