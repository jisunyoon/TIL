# 가상 메모리 (Virtual Memory)

프로세스마다 **가짜 주소 공간**을 주고, 실제 쓰는 부분만 RAM에 올려서 **물리 메모리보다 많이 쓸 수 있게** 하는 방식

---

## 핵심 아이디어

- 프로세스는 **가상 주소 공간**(자기만의 가짜 주소)을 본다
- 프로그램 전체를 RAM에 다 안 올리고, **지금 실행 중인 부분만 RAM**에 올림
- 안 쓰는 부분은 **디스크**에 둔다
- → RAM(물리 메모리)이 작아도, 디스크를 곁들여 **더 큰 것처럼** 쓸 수 있다

```
가상 주소 공간 (프로세스가 보는 것, 큼)
   ├─ 지금 쓰는 부분   → RAM에 올림 (실제 물리 메모리)
   └─ 안 쓰는 부분     → 디스크에 보관 (필요할 때 불러옴)
```

---

## 물리 메모리보다 많이 쓰는 원리

### ① 스와핑 (Swapping)

- **지금 쓰는 것만 RAM**, 안 쓰는 건 **디스크(스왑 영역)**로 내림
- 나중에 필요해지면 디스크 → RAM으로 불러오고, 대신 다른 안 쓰는 걸 RAM → 디스크로 내림
- 그래서 RAM 8GB여도 그보다 많은 메모리를 쓰는 것처럼 동작

### ② 프로세스 격리

- 프로세스마다 **각자의 가상 주소 공간**을 줌 (다들 0번지부터 시작하는 것처럼)
- 실제 물리 위치는 **OS가 뒤에서 매핑**(가상 주소 → 물리 주소 변환)
- → 프로세스끼리 주소가 안 겹치고 **서로 격리됨** (한 프로세스가 다른 프로세스 메모리 못 건드림)

---

## 주소 변환

- 가상 주소 ↔ 물리 주소 매핑은 **MMU(하드웨어)** + **페이지 테이블**이 처리
- 메모리를 **페이지**라는 일정 크기 조각으로 나눠서 관리

---

## 트레이드오프 — 스래싱

- 디스크는 RAM보다 **훨씬 느림**
- 디스크에 있던 걸 **너무 자주 불러와야 하면** 오히려 느려짐 → **스래싱(thrashing)**
- 그래도 "아예 못 돌리는 것보단 낫다"는 개념

> 한 줄: 가상 메모리 = 프로세스에 **가짜 주소 공간**을 주고 **쓰는 것만 RAM·나머지는 디스크**에 둬서, **물리 메모리보다 많이 쓰고** 프로세스 **격리**까지 얻는 방식.
