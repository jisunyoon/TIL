# Event Loop / Microtask / async·await

JS가 싱글 스레드인데도 어떻게 비동기를 처리하는지, 그 순서가 어떻게 정해지는지

---

## 1. 이벤트 루프란

> **콜스택이 비었는지 계속 확인하다가, 비면 대기 줄에서 다음 작업을 꺼내오는 반복 장치**

JS 엔진 혼자 하는 게 아니라, **콜스택 + 큐 + 이벤트 루프**가 협력해서 돌아간다.

```
콜스택(지금 하는 일)
   └─ 오래 걸리는 일은 브라우저(Web API)가 대신 처리
        └─ 끝나면 큐(태스크 / 마이크로태스크)에 콜백을 넣음
             └─ 콜스택이 비면 이벤트 루프가 큐에서 꺼내 콜스택에 올림
```

---

## 2. 콜스택 (Call Stack)

- JS가 **지금 실행 중인 일**을 쌓아두는 곳
- 함수 실행하면 쌓이고(push), 끝나면 빠진다(pop)
- 자료구조 = **스택** (push로 넣고 pop으로 뺌, LIFO)

---

## 3. 두 개의 큐

| | 무엇이 대기하나 | 자료구조 | 우선순위 |
|---|---|---|---|
| **태스크 큐** (Task Queue) | `setTimeout`, `setInterval`, 클릭 이벤트 | 큐 (앞에서 shift로 뺌, FIFO) | 낮음 |
| **마이크로태스크 큐** (Microtask Queue) | `Promise.then`, `async/await` | 큐 (FIFO) | **가장 높음** |

---

## 4. 큐가 두 개인 이유 = 우선순위

> **규칙: 태스크(일반) 하나를 처리할 때마다, 마이크로태스크(급한 것)는 "싹 다" 먼저 비운다.**

- 태스크 1개 실행 → 마이크로태스크 큐 **전부** 비우기 → 다시 태스크 1개 → 또 마이크로태스크 전부 비우기 …
- 즉 마이크로태스크가 남아 있으면 다음 태스크로 절대 안 넘어감

> **"우선순위 높음"의 의미** — 어디까지나 *대기 줄 안에서의* 순번이다.
> 기본(동기) 코드가 먼저 다 돌고 → 그다음 대기 중인 것들 중에서 마이크로태스크가 태스크보다 빠른 것.
> 동기 코드는 대기 줄에 서지 않고 지금 실행 중이라 애초에 경쟁 상대가 아니다.
> 순서: **동기 코드 → 마이크로태스크 전부 → 태스크 하나 → (다시 마이크로태스크 전부) → …**

---

## 5. Promise가 setTimeout보다 먼저인 이유

- `Promise`는 **마이크로태스크 큐**, `setTimeout`은 **태스크 큐**
- 마이크로태스크를 **전부 비운 다음에야** 태스크로 넘어가므로
- → 둘 다 대기 중이면 항상 **Promise가 먼저** 실행된다

---

## 6. async 함수가 Promise로 바뀌는 과정

- `async` 함수는 **무조건 Promise를 반환**한다 (return 값은 자동으로 resolve)
- `await`를 만나면 거기서 **멈추고**, 그 아랫줄을 `.then` 콜백(= 마이크로태스크)으로 등록한다
- 즉, **`await` 위 = 그 자리에서 바로 실행**, **`await` 아래 = 나중에(마이크로태스크) 실행**

```js
async function f() {
  console.log(1);       // await 위 → 지금 바로 실행
  await null;           // 여기서 멈춤, 아랫줄을 마이크로태스크로 등록
  console.log(3);       // await 아래 → 나중에(마이크로태스크)
}

console.log(0);
f();
console.log(2);         // f() 안의 await 아래보다 먼저 (동기 코드가 우선)

// 출력: 0 → 1 → 2 → 3
```

> `await`는 사실상 "여기까지 실행하고, 나머지는 `.then`으로 미뤄줘"의 문법 설탕(syntactic sugar).
