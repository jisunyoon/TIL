# 배열 vs 링크드리스트

둘 다 데이터를 여러 개 담는 자료구조지만, 저장 방식이 달라 잘하는 연산이 반대다.

---

## 배열 (Array)

데이터를 **순서대로(연속된 메모리에) 저장**하고 **인덱스(번호)로 접근**한다.

| 연산 | 복잡도 | 이유 |
|---|---|---|
| 접근 (인덱스) | **O(1)** | 몇 번째인지 알면 위치를 바로 계산해 꺼냄 |
| 탐색 (값 찾기) | O(n) | 처음부터 훑어야 함 |
| 중간 삽입/삭제 | O(n) | 뒤엣것들을 다 밀어야 함 |

---

## 링크드리스트 (Linked List)

각 데이터가 **"다음 주소"를 가리키며** 사슬처럼 연결된다. (연속 메모리 아님)

| 연산 | 복잡도 | 이유 |
|---|---|---|
| 접근 | O(n) | 인덱스가 없어 처음부터 따라가야 함 |
| 중간 삽입/삭제 | **O(1)** | 연결(포인터)만 바꾸면 됨, 뒤엣것 안 밀어도 됨 |

> 단, 삽입/삭제가 O(1)인 건 **그 위치를 이미 알고 있을 때**.
> 위치를 찾아서 넣으면 탐색 O(n)이 붙어 O(n)이 된다. (연결 바꾸는 행위 자체만 O(1))

---

## 비교 정리

| | 접근 | 중간 삽입/삭제 | 특징 |
|---|---|---|---|
| **배열** | O(1) | O(n) | 인덱스로 바로 접근, 대신 밀기 비용 |
| **링크드리스트** | O(n) | O(1)* | 밀 필요 없음, 대신 순차 접근만 |

> 잘하는 게 **정반대**다. 인덱스 접근이 잦으면 배열, 중간 삽입/삭제가 잦으면 링크드리스트.
